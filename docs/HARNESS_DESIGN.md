# Agent Harness design and acceptance

Updated 2026-11-05. The architecture reference is DeepSeek Harness commit [`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159), particularly its [architecture](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/architecture.md), [tool pipeline](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/tool-execution-pipeline.md) and [agent loop](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/agent-loop/README.md). This implementation adapts the concepts to a private CS2 data application; it does not embed the DSH desktop runtime or claim API compatibility. New implementation code is original. Upstream DSH is MIT, Copyright 2026 DeepSeek; copying implementation later requires preserving its license.

| Capability | Implementation |
| --- | --- |
| Composable tools | `agent-registry.mjs` accepts trusted build-time declarations, validates dependencies and schemas, composes per-stage tool snapshots and supports safe reverse disposal. It is used by the actual model request builder, not just a capability list. Model input cannot install executable plugins. |
| Dynamic orchestration | Existing evidence-backed DAG plus `edit_task_workflow`: revision-checked atomic transactions, forward dependencies, graph validation and rollback on failed persistence. Read, visualization validation and presentation remain distinct operations. |
| Observable tasks | Server workflow projection and client dependency lanes show ready, active, blocked, retryable, completed, deferred and cancelled steps, target match/round/clip, plan revision and actual settled tool activity. A task node is not an independently running model Agent. |
| Tool lifecycle | Input validation, authorization/source constraints, execution, immutable query archive, observed evidence and typed activity events. Existing batching loads independent immutable statistics packs concurrently; state/CAS/archive publication remains deterministic. |
| Large-data processing | Lossless source-addressed prepared statistics, typed filters/grouping/aggregates/quantiles, batch computations, exact field projection and compact model views. The model need not read every row. |
| Faster preparation | Bulk source evidence resolves through one current-turn pack pointer per match, then checks exact membership and sealed content, avoiding per-round alias-trie I/O. Repeated source registration grants no new progress credit. Prepared packs remain owner/ref/detail/sha validated across conversations. |
| Raw evidence | `discover_raw_data`, `query_raw_data` and bounded `read_raw_data_batch` expose stored parsed frames/events with field selection, predicates, missing/null semantics and original locators. See `MCP_RAW_QUERIES.md`. |
| Context and recovery | Existing bounded working sets, immutable query archives, model-view projections, persistent sessions, source generations, CAS leases, manual provider-error recovery and finite repair progress remain enforced. Old-turn references are not accepted as new measurements. |
| Streaming | UTF-8-safe typed SSE, sequence checks, response lifecycle, stage artifacts, cancellation and reload recovery. Already-dispatched provider responses keep their independent hard/idle timeout. |
| Provider reasoning | The user explicitly enabled DeepSeek's documented `response.reasoning_text.delta` / plaintext terminal reasoning. It has a separate escaped stream and default-collapsed view, current-turn recovery and per-attempt labels. Encrypted/unknown reasoning, keys, prompts and raw tool arguments are not exposed. The display retains the latest 64 KiB / 8 attempts and clearly marks omitted older text; this does not constrain model generation. |
| Cross-page UI | The coach page retains the full workbench. Other pages use one consistent expandable side card, preserve the shared session, and return keyboard focus on collapse. |
| Evaluation | Handler/stream/runtime/UI/query tests cover protocol, provenance, rollback, injection escaping, stale-event protection, cache isolation and numerical computation. Builds and production acceptance are separate receipts. |

Workers provide 128 MB isolates rather than a desktop process environment. Arbitrary shell, PTY, filesystem, LSP, browser automation, unreviewed third-party plugin execution and separate model subagents have not been transplanted. The portable local capture assistant remains on demand, with exact game-settings restoration; no permanent service is introduced. This release must not be described as a complete DSH port.

Remaining work includes benchmarking the reduced source preparation I/O in production, deeper plugin execution-provider seams if an appropriate trusted runtime is selected, and independent model-worker identities if actual multi-agent execution is required. None of the task display lanes imply those capabilities already exist.
